# AI Admissions Essay Detector

A tool that scores college admissions essays for likely AI involvement, sentence by sentence, and shows the evidence behind every score instead of handing back a bare verdict.

## What it does

Paste an essay in and get back:

- **A sentence-by-sentence heatmap.** Each sentence is shaded on a continuous scale from human-like to AI-like — not a binary flag.
- **Evidence, not assertions.** Click any sentence to see the three features that drove its score, each one phrased against where it falls in a distribution of real human writing ("higher than 87% of human training sentences"), with a bar showing how much it mattered.
- **A token-level heatmap.** See which words GPT-2 found predictable and which ones surprised it — the raw signal the rest of the system is built on.
- **Transition flags.** Spots where an essay's score jumps abruptly between sentences, the kind of pattern you'd expect from a human paragraph an AI tool later polished.
- **An essay-level verdict** — Likely Human, Inconclusive, or Likely AI — with a confidence score that gets dampened when the sentence-to-sentence scores are unusually erratic.

## The language model is an instrument, not a judge

GPT-2 does exactly one job here: producing token-level log-probabilities — perplexity, and the rank of each actual token in the model's predicted distribution (GLTR). It never outputs a verdict, a label, or an explanation. Every judgment the UI shows — the sentence score, the essay verdict, the evidence text — comes from a classifier we trained ourselves, plus deterministic logic on top of it. Nothing in this app calls a hosted chat or completion API.

That matters for how the "why" gets computed too. The classifier is a `GradientBoostingClassifier`, a tree ensemble with no linear coefficients to read off, so the evidence panel works by perturbation: take a sentence's real feature values, swap one feature to what's typical for human writing, re-score, and measure how much the prediction moved. Do that for each feature and rank by magnitude. It's slower to compute than reading a coefficient, but it's still just arithmetic on numbers we control — never text generated by a model.

## Stack

| Layer | Choice |
|---|---|
| Frontend | React + Vite + Tailwind |
| Backend | Python 3.12, FastAPI |
| ML | scikit-learn (`GradientBoostingClassifier`, standardized features) |
| NLP | spaCy (`en_core_web_sm`) for sentence segmentation and POS/dependency parsing |
| Language model (instrument only) | Hugging Face Transformers, `gpt2`, CPU |
| Data tooling | pandas, numpy, joblib |

No GPU needed anywhere — perplexity and GLTR both come from a single GPT-2 forward pass per essay, and CPU inference on a few hundred tokens is fast enough that it doesn't matter.

## Running it locally

```bash
# Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m spacy download en_core_web_sm
uvicorn app.main:app --port 8000
```

```bash
# Frontend, separate terminal
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The classifier ships pre-trained (`backend/app/models/*.joblib`), so no training step is required just to run the app. To retrain from scratch or reproduce the evaluation, the scripts are in `backend/scripts/`, and `DOCUMENTS/IMPLEMENTATION.md` has the full build history and the order to run them in.

## How well does it actually work?

The classifier trains on 2,246 essays: 530 real human essays from four sources, 500 real AI essays from Gemini, another 160 from OpenAI and Anthropic, and a 1,056-essay slice of DAIGT-v2 covering 16 different AI generators in a different genre (persuasive writing, not admissions essays). Twelve features go in — perplexity, three GLTR rank-bucket aggregates, and eight stylometry measures. Full methodology and every intermediate result are in [`docs/EVALUATION.md`](docs/EVALUATION.md); the short version:

**It's strong on essays similar to what it trained on.** On admissions essays like the ones it learned from, sentence-level accuracy sits around 71-72%. That number looks unremarkable next to the actual verdict accuracy, though — averaging many sentence scores into one essay-level call gets you to roughly 95% balanced accuracy, and that's the number that actually describes what happens when you paste an essay in. On the 16 AI models covered by DAIGT-v2, in a completely different genre, essay-level accuracy is 93%.

**It's weak on AI tools it's never seen.** A held-out set of real OpenAI and Anthropic essays — never touched during training — gets caught only 35% of the time at the essay level. That's real progress (it started at 7.5%, before we added more of that generator family to training), but it's still the honest bottom line: paste in something from a brand-new AI tool and there's a good chance it reads as Likely Human or Inconclusive rather than Likely AI.

**Passage-level localization works, imperfectly.** Splice a real AI paragraph into a real human essay and the sentence highlighter catches it with an F1 around 0.54 for a clean continuation, 0.37 for the harder case where AI text is spliced into the middle with human writing on both sides.

**Fairness was investigated, not assumed.** Scored against PERSUADE and ELLIPSE — real student writing with demographic labels — the strict false-positive rate (a confident "Likely AI" call on genuine human writing) sits near zero across every group. The broader false-positive rate (anything short of a confident "Likely Human") has some real gaps by race, ELL status, and economic background, and those gaps move around more than we'd like as the training data changes. Full numbers and the investigation behind them are in [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md).

Along the way we tried a few things that didn't pan out and said so rather than quietly dropping them: a nonlinear classifier swap that helped in-genre accuracy at a real cost to cross-genre generalization, a tree-depth increase that looked free until it turned out to hurt recall on unseen AI tools specifically. Both decisions, and the testing that led to them, are logged in `DOCUMENTS/IMPLEMENTATION.md`.

## The honest limitations

The full, prioritized list is in [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md). Two matter most:

1. **It doesn't reliably catch AI tools it's never trained on.** 35% recall on genuinely novel generators is real progress from where it started, but it means most essays from an unfamiliar AI tool will still come back Inconclusive or Likely Human. Treat any verdict on an essay from an unusual or very recent AI tool with real skepticism — the tool is much more trustworthy on the generators it actually knows.
2. **There's a measured fairness gap.** Detectors like this one have a known tendency to flag writing from ELL students and other groups whose prose GPT-2 finds less predictable for reasons that have nothing to do with AI authorship. We looked for it, found it, traced it to a specific mechanism, and are disclosing the current numbers rather than hiding them — see `docs/LIMITATIONS.md` for what's fixed and what isn't.

This is a research and demonstration tool. It shouldn't be the sole basis for an academic-integrity decision about a real student.
